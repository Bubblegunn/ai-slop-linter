ai-slop-linter playground

Paste a commit message, a pull request description or a README. It lists the patterns that mark writing as machine-made, with a line, a column, a reason and its source, and offers a fix where the fix is a character swap or a phrase with a shorter form.

What this is not

  • Not an authorship detector. It never outputs a probability that a model wrote the text, and it cannot tell you who typed it. A person who writes delve gets the same finding as a model.
  • A clean pass is not proof of anything beyond the absence of the listed tells. Text that passes can still be wrong, or empty.
  • Your text never leaves this device. The linter is a rule engine that runs in this tab. There is no account, no analytics, no error reporting and no storage: reload the page and whatever you typed is gone. After the page has loaded you can disconnect from the network and everything here still works.
  • These are style rules, not objective errors. Each one says when a maintainer should switch it off rather than obey it.

Your text

0 characters. Up to 100,000 characters. The page re-lints shortly after you stop typing, on this tab's own thread, and past roughly that much text the pause is long enough to feel while you type. No commit message, pull request description or README this tool is aimed at is that long. It is a product limit picked for responsiveness, not a threshold with evidence behind it.

    Keep it in your own workflow
    
    
    The page is a way to see what the tool says. It is meant to be run where you
    write, not here.
    
    
    npx ai-slop-linter README.md          # lint one file
npx ai-slop-linter --commit           # the last commit message
npx ai-slop-linter README.md --fix    # apply the safe fixes in place
    
    
    There is also a GitHub Action for pull requests, a commit-msg hook, a
    commitlint rule and an agent skill.
    The README has all of them,
    with the rule table, the measured false alarms on a fixed corpus, and what the tool cannot
    show.
